MATRIZ CONSOLIDADA - TABLA POR TABLA
================================================================================

TABLA: exercise_attempts
├─ Acción: ENVÍO DE EJERCICIO
├─ Frecuencia: Cada intento (múltiples permitidos)
├─ Campos críticos:
│  ├─ submitted_answers (JSONB) - respuestas del usuario
│  ├─ is_correct (BOOLEAN) - resultado de validación
│  ├─ score (INTEGER) - puntuación 0-100
│  ├─ xp_earned (INTEGER) - recompensa XP
│  ├─ ml_coins_earned (INTEGER) - recompensa monedas
│  ├─ hints_used (INTEGER) - contador de pistas usadas
│  ├─ time_spent_seconds (INTEGER) - tiempo en ejercicio
│  └─ attempt_number (INTEGER) - número de intento (auto-incremental)
├─ Validación: Via SQL validate_and_audit()
├─ Rewards:
│  ├─ XP = MAX(0, score - (hints_used * 10))
│  └─ COINS = MAX(0, FLOOR(score/10) - (comodines * 2))
└─ Dependencias: Dispara 5 actualizaciones en cascade

---

TABLA: user_stats
├─ Acción: CUALQUIER ACTIVIDAD GAMIFICADA
├─ Frecuencia: Múltiple por ejercicio (XP, coins, counters)
├─ Campos críticos:
│  ├─ total_xp (INTEGER) - acumulado total (TRIGGER sensible)
│  ├─ ml_coins (INTEGER) - balance actual
│  ├─ level (INTEGER) - nivel del usuario
│  ├─ current_rank (ENUM: Ajaw, Nacom, Ah K'in, Halach Uinic, K'uk'ulkan)
│  ├─ rank_progress (NUMERIC 0-100) - progreso al siguiente rango
│  ├─ exercises_completed (INTEGER) - contador
│  ├─ perfect_scores (INTEGER) - ejercicios con 100%
│  ├─ last_activity_at (TIMESTAMP) - TRIGGER auto
│  └─ last_login_at (TIMESTAMP) - manual tracking
├─ Auto-actualizaciones:
│  ├─ AFTER UPDATE total_xp:
│  │  ├─► Recalcula level si supera umbral
│  │  ├─► Promueve rank si aplica (trigger)
│  │  └─► Otorga bonus +50 ML Coins
│  └─ ALWAYS: updated_at = NOW()
└─ Índices: 10 índices estratégicos para leaderboards

---

TABLA: module_progress
├─ Acción: COMPLETAR EJERCICIO (primer intento correcto en módulo)
├─ Frecuencia: 1 sola vez por módulo (luego solo timestamps)
├─ Campos críticos:
│  ├─ status (ENUM: not_started → in_progress → completed)
│  ├─ progress_percentage (INTEGER 0-100)
│  ├─ completed_exercises (INTEGER) - ejercicios correctos
│  ├─ total_exercises (INTEGER) - ejercicios activos en módulo
│  ├─ total_xp_earned (INTEGER) - suma de XP en módulo
│  ├─ total_ml_coins_earned (INTEGER) - suma de monedas
│  ├─ started_at (TIMESTAMP) - cuando comenzó
│  ├─ completed_at (TIMESTAMP) - cuando alcanzó 100%
│  └─ last_accessed_at (TIMESTAMP) - última vez que accedió
├─ Lógica UPSERT:
│  ├─ Si es PRIMER ejercicio correcto: recalcula todo
│  ├─ Si NO es el primero: solo actualiza timestamps
│  └─ Si progress >= 100%: status = 'completed'
└─ Constraint: progress_percentage CHECK (0 <= % <= 100)

---

TABLA: ml_coins_transactions
├─ Acción: GANAR O GASTAR MONEDAS
├─ Frecuencia: 1 por cada movimiento económico
├─ Campos críticos:
│  ├─ amount (INTEGER) - positivo si gana, negativo si gasta
│  ├─ transaction_type (ENUM) - EARNED_EXERCISE, SPENT_HINT, SPENT_SHOP, etc
│  ├─ balance_before (INTEGER) - saldo anterior
│  ├─ balance_after (INTEGER) - saldo nuevo
│  ├─ description (VARCHAR) - motivo de transacción
│  ├─ reference_id (UUID) - ID del ejercicio/item
│  ├─ reference_type (ENUM) - 'exercise', 'shop_item', 'mission'
│  ├─ multiplier (NUMERIC) - 1.0 por defecto
│  └─ metadata (JSONB) - datos adicionales
├─ Auditoría: OBLIGATORIA
│  ├─ No se actualizan monedas sin transacción
│  └─ Cada transacción tiene balance antes/después
└─ Queries: Historial completo recuperable

---

TABLA: missions
├─ Acción: COMPLETAR EJERCICIO (si hay misión con objetivo "complete_exercises")
├─ Frecuencia: DINÁMICA (auto-update cada ejercicio)
├─ Campos críticos:
│  ├─ objectives[] (JSONB ARRAY):
│  │  ├─ type (ENUM) - complete_exercises, correct_streak, study_time
│  │  ├─ target (INTEGER) - objetivo final
│  │  ├─ current (INTEGER) - progreso actual (incrementa cada ejercicio)
│  │  └─ description (VARCHAR)
│  ├─ progress (INTEGER) - % basado en objectives
│  ├─ status (ENUM) - active → in_progress → completed → claimed
│  ├─ rewards (JSONB):
│  │  ├─ ml_coins (INTEGER) - 25-150 según tipo
│  │  └─ xp (INTEGER) - 30-100 según tipo
│  └─ end_date (TIMESTAMP) - expiración
├─ Tipos de misiones:
│  ├─ DAILY: 3 misiones/día, expiran a medianoche
│  ├─ WEEKLY: 2 misiones/semana, expiran domingo
│  └─ SPECIAL: eventos manuales
└─ Reclamación: MANUAL (usuario hace click en "Claim")

---

TABLA: user_ranks
├─ Acción: ALCANZAR UMBRAL DE XP PARA NUEVO RANGO
├─ Frecuencia: 1 sola vez por rango (5 máximo en carrera)
├─ Campos críticos:
│  ├─ user_id (UUID) - referencia
│  ├─ rank_name (ENUM) - Ajaw, Nacom, Ah K'in, Halach Uinic, K'uk'ulkan
│  ├─ rank_number (INTEGER 1-5)
│  ├─ unlock_date (TIMESTAMP) - cuándo alcanzó
│  ├─ xp_at_promotion (INTEGER) - XP total en ese momento
│  ├─ bonus_ml_coins (INTEGER) - +50 otorgado
│  └─ metadata (JSONB):
│     └─ unlock_features (ARRAY) - features desbloqueadas
├─ Creación: AUTOMÁTICA VÍA TRIGGER
│  └─ Cuando user_stats.total_xp >= umbral
└─ Histórico: Tabla de auditoría de promociones

---

TABLA: auth_management.profiles
├─ Acción: EDITAR PERFIL MANUALMENTE (SettingsPage)
├─ Frecuencia: Manual por usuario
├─ Campos editables:
│  ├─ display_name (VARCHAR) - nombre público
│  ├─ bio (TEXT) - biografía
│  ├─ avatar_url (VARCHAR) - foto de perfil
│  ├─ location (VARCHAR) - ubicación
│  ├─ notification_preferences (JSONB):
│  │  ├─ email_notifications (BOOLEAN)
│  │  ├─ push_notifications (BOOLEAN)
│  │  └─ daily_digest (BOOLEAN)
│  ├─ privacy_settings (JSONB):
│  │  ├─ show_in_leaderboard (BOOLEAN)
│  │  ├─ allow_friend_requests (BOOLEAN)
│  │  └─ show_progress (BOOLEAN)
│  ├─ metadata (JSONB) - custom fields
│  └─ updated_at (TIMESTAMP) - AUTO
└─ Validaciones: Ninguna especial (frontend valida)

================================================================================
FLUJO DETALLADO: ENVÍO DE EJERCICIO (CASO MÁS COMPLEJO)
================================================================================

ENTRADA: Usuario hace click en "Enviar Respuestas" en ExercisePage
├─ Datos: {answers: {...}, hintsUsed: 2, startedAt: 1732450800}
└─ Respuesta esperada: {score, xpEarned, rankUp?, feedback, achievements?}

PASO 1: VALIDATE ANSWERS (FE-059)
├─ ExerciseAnswerValidator.validate(exercise_type, answers)
├─ Si falla: RECHAZA (no procede a BD)
└─ Si OK: continúa

PASO 2: CALL VALIDATE_AND_AUDIT (PostgreSQL)
├─ SELECT * FROM educational_content.validate_and_audit(
│   exercise_id, user_id, answers, attempt_number, metadata
│ )
├─ Retorna: {score: 85, is_correct: true, feedback, audit_id}
└─ Side effect: INSERT en exercise_validation_audit (auto)

PASO 3: CALCULATE REWARDS
├─ calculateXpReward(85, 2 hints) = 85 - 20 = 65 XP
├─ calculateCoinsReward(85, 0 comodines) = 8 - 0 = 8 coins
└─ isPerfectScore = false (hints usados)

PASO 4: INSERT EXERCISE_ATTEMPTS
├─ INSERT {
│  user_id, exercise_id, attempt_number: 2,
│  submitted_answers: {...}, is_correct: true, score: 85,
│  xp_earned: 65, ml_coins_earned: 8, hints_used: 2,
│  submitted_at: NOW(), ...
│ }
└─ Retorna: ID del nuevo intento

PASO 5: AWARD REWARDS
├─ A) UPDATE user_stats SET total_xp += 65
│  └─ TRIGGER: trg_check_rank_promotion_on_xp_gain
│     ├─ Si total_xp >= 3000: promote_to_next_rank()
│     │  ├─ UPDATE current_rank = 'Ah K\'in'
│     │  ├─ UPDATE rank_progress = 0
│     │  ├─ INSERT user_ranks (histórico)
│     │  └─ bonus_ml_coins = 50
│     └─ UPDATE updated_at = NOW()
│
├─ B) UPDATE user_stats SET ml_coins += 8
│  └─ UPDATE ml_coins_earned_total += 8
│  └─ Check daily reset si necesario
│
└─ C) INSERT ml_coins_transactions
   ├─ amount: 8, transaction_type: 'EARNED_EXERCISE'
   ├─ reference_id: exercise_id
   ├─ balance_before/after: registrado
   └─ created_at: NOW()

PASO 6: UPDATE MODULE_PROGRESS
├─ Obtener module_id del ejercicio
├─ Contar ejercicios correctos = 2 (incluyendo este)
├─ UPSERT module_progress:
│  ├─ completed_exercises: 2
│  ├─ progress_percentage: 40 (2/5 * 100)
│  ├─ status: 'in_progress'
│  ├─ total_xp_earned: prev + 65
│  └─ last_accessed_at: NOW()
└─ Si progress >= 100%: completed_at = NOW()

PASO 7: UPDATE MISSIONS (DINÁMICO)
├─ Buscar misiones activas del usuario
├─ Si hay misión con objetivo 'complete_exercises':
│  ├─ UPDATE objectives[0].current = 2
│  ├─ Recalcular progress = (2/3 * 100) = 67%
│  └─ Si current >= target: status = 'completed'
└─ UPDATE missions.updated_at = NOW()

PASO 8: RETORNAR AL FRONTEND
├─ Response: {
│  attemptId: uuid,
│  score: 85,
│  isPerfect: false,
│  rewards: {xpEarned: 65, mlCoins: 8},
│  rankUp: null,  // O {oldRank: 'Nacom', newRank: 'Ah K\'in', ...}
│  feedback: {overall: "Great job!", answerReview: [...]},
│  achievements: [],
│  createdAt: timestamp
│ }
└─ Frontend:
   ├─ showFeedbackModal()
   ├─ Si isPerfect: confetti animation
   ├─ Si rankUp: special celebration
   └─ After 3s: navigate to next exercise

TOTAL OPERACIONES BD: 7-10 writes + 3-5 reads
LATENCIA: Típicamente 100-200ms

================================================================================
VALIDACIONES Y RESTRICCIONES
================================================================================

NIVEL DE CAMPO:
├─ user_stats.level > 0 (constraint)
├─ user_stats.ml_coins >= 0 (constraint)
├─ user_stats.rank_progress 0-100 (constraint)
├─ module_progress.progress_percentage 0-100 (constraint)
├─ exercise_attempts.score >= 0 (constraint)
├─ exercise_attempts.attempt_number > 0 (constraint)
├─ missions.progress >= 0 (lógica backend)
└─ all created_at/updated_at NOT NULL (trigger)

LÓGICA DE NEGOCIO:
├─ Score = amount * multiplier (si aplica)
├─ XP_EARNED = MAX(0, score - hints_penalty)
├─ COINS_EARNED = MAX(0, FLOOR(score/10) - comodines_penalty)
├─ Rango solo sube (nunca baja)
├─ Misión se completa solo una vez
├─ Ejercicio puede reintentarse (múltiples attempts)
├─ Submission (teacher-graded) se envía 1 sola vez
└─ Monedas NO pueden ser negativas (validación en spendCoins)

================================================================================
DEPENDENCIAS Y IMPACTO EN CASCADE
================================================================================

Si falla validación en exercise_attempts:
└─ STOP - No procede a ninguna otra tabla

Si falla INSERT exercise_attempts:
├─ Rollback de transaction
└─ Retorna error al frontend

Si es correcto exercise_attempts:
├─ GUARANTEE: user_stats se actualiza
├─ GUARANTEE: ml_coins_transactions se inserta
├─ GUARANTEE: module_progress se actualiza
├─ GUARANTEE: missions se actualizan
└─ CONDITIONAL: user_ranks si alcanza umbral

Si user_stats.total_xp UPDATE:
├─ AUTOMATIC: trigger check_rank_promotion ejecuta
├─ AUTOMATIC: possible INSERT user_ranks
├─ AUTOMATIC: possible UPDATE current_rank
└─ AUTOMATIC: updated_at = NOW()

MONITOREO Y ALERTAS RECOMENDADAS

IMPORTANTE:
- Retrasos en updateModuleProgress > 500ms
- Missions no completándose auto
- Transacciones duplicadas en ml_coins_transactions

INFORMATIVO:

- Uso de hints por ejercicio
- Conversión de recompensas (score → XP → coins)
